# GEQ Zoom Analysis — External Sources

- [FFmpeg Filters Documentation](https://ffmpeg.org/ffmpeg-filters.html) documents `geq` as a generic equation-based video filter, lists `zoompan` separately, and lists the CUDA hardware-frame helpers `hwupload_cuda` and `hwdownload` among its video filters. The documented filtergraph model permits chained processing, but a hardware-only chain requires compatible frame formats throughout.
- [NVIDIA Video Codec SDK — Using FFmpeg with NVIDIA GPU Hardware Acceleration](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/ffmpeg-with-nvidia-gpu/index.html) documents GPU-side transcoding with CUDA hardware frames and NVENC. It shows `scale_cuda`/`scale_npp` for GPU resizing and explains that keeping frames in GPU memory eliminates system/video-memory transfers. It also shows `hwupload` for software-decoded inputs before GPU scaling/encoding.
- The installed local FFmpeg 8.1 build was tested on the connected Windows machine: `cuda`, `h264_nvenc`, `hwupload_cuda`, and `scale_cuda` are available; `scale_npp` and GPU overlay/compositor filters are absent. An isolated standard-YUV CUDA scale-to-NVENC clip succeeded when CUDA frames remained on-device. The same path did not accept the Finance JPEG source without a format-conversion boundary.
